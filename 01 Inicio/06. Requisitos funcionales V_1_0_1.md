## 1. Marco de Elicitación Holística y Ética

El proceso de elicitación de requisitos se realizó bajo un enfoque **holístico, glocal y ético**, considerando:

### 1.1 Grupos de usuarios diversos
- **Operadores de logística** (Gerente de Operaciones de DistriRápido).
- **Conductores de última milla** (nivel básico de alfabetización digital, muchos viven en distritos alejados).
- **Clientes finales** (bodegueros y pequeños comerciantes de San Juan de Lurigancho, El Agustino, Santa Anita y Ate).
- **Stakeholders académicos** (docente del curso).
- **Usuarios indirectos**: autoridades de tránsito (MTC) y proveedores de datos de tráfico.

### 1.2 Contexto local (glocal)
- Direcciones no estandarizadas en San Juan de Lurigancho.
- Restricción vehicular por dígito de placa (D.S. N° 033-2012-MTC).
- Congestión extrema en Av. Próceres de la Independencia y Av. Fernando Belaúnde Terry.
- Jornadas máximas de 8 horas y descansos obligatorios (Ley N° 30224).
- Alta incidencia de robos en zonas específicas (Ciudades Satélite de Santa Anita).
- Conectividad limitada (2G/3G) en zonas periféricas.
- Costos locales de combustible (S/ 17.50/galón diésel) y mantenimiento (S/ 1.20/km).

### 1.3 Perspectiva ética
- Cumplimiento estricto de la **Ley N° 29733** (Protección de Datos Personales).
- Diseño inclusivo (WCAG 2.1 AA) para conductores con baja familiaridad tecnológica.
- Minimización de impacto ambiental y acústico.
- Transparencia en el uso de datos de geolocalización y preferencias de clientes.
- Evitar sesgos algorítmicos que penalicen zonas de alta densidad o vulnerabilidad.

### 1.4 Técnicas de elicitación aplicadas
- Análisis documental de la consigna del proyecto y de normativa peruana.
- Simulación de entrevistas con perfiles de Gerente de Operaciones y Conductores.
- Análisis de escenarios de tráfico real de Lima Este.
- Validación cruzada con restricciones ambientales y sociales locales.

## 2. Catálogo de Requisitos Funcionales (Especificación Atómica)

### RF-001: Gestión de Flota
- **Descripción Atómica:** El sistema debe permitir registrar, consultar, actualizar y desactivar vehículos de la flota cuando un usuario autorizado ingrese o modifique los datos del vehículo.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold (Camino Ideal Principal)
DADO que el usuario autenticado tiene rol de Administrador u Operador  
CUANDO registra un vehículo con placa, tipo, capacidad de carga (kg), consumo de combustible (km/L), factor de emisión de CO₂ (kg CO₂/km) y año de fabricación  
ENTONCES el sistema almacena el registro, asigna un identificador único y confirma la operación con mensaje de éxito.

#### Ruta Feliz (Flujos Alternativos Válidos)
DADO que el vehículo ya existe en el sistema  
CUANDO el usuario actualiza el factor de emisión o el estado (activo/inactivo)  
ENTONCES el sistema guarda los cambios y registra la modificación en el historial de auditoría.

#### Ruta Infeliz (Casos Borde y Manejo de Errores)
DADO que se intenta registrar un vehículo con placa duplicada o datos inválidos (capacidad negativa, año futuro)  
CUANDO el usuario envía el formulario  
ENTONCES el sistema rechaza la operación, mantiene el estado consistente y muestra un mensaje de error específico (“La placa ya se encuentra registrada” / “Datos de capacidad inválidos”).

---

### RF-002: Gestión de Pedidos
- **Descripción Atómica:** El sistema debe permitir registrar, consultar, actualizar y cancelar pedidos de entrega cuando un usuario autorizado proporcione los datos del pedido.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que el usuario autenticado tiene permisos de Operador  
CUANDO registra un pedido con ID de cliente, dirección (o punto de referencia), coordenadas GPS, peso, volumen, ventana de tiempo, prioridad y tipo de producto  
ENTONCES el sistema almacena el pedido, calcula el estado inicial “Pendiente” y confirma el registro.

#### Ruta Feliz
DADO que la dirección no tiene nomenclatura estándar  
CUANDO el usuario ingresa un punto de referencia (ej. “frente a la bodega El Ahorro”) junto con coordenadas aproximadas  
ENTONCES el sistema acepta el registro y marca el pedido con bandera de “georreferencia aproximada”.

#### Ruta Infeliz
DADO que se ingresan coordenadas fuera del área de cobertura (SJL, El Agustino, Santa Anita, Ate) o una ventana de tiempo inválida  
CUANDO se intenta guardar el pedido  
ENTONCES el sistema rechaza la operación y muestra el mensaje de error correspondiente.

---

### RF-003: Generación de Rutas Optimizadas
- **Descripción Atómica:** El sistema debe calcular un conjunto de rutas optimizadas para los pedidos pendientes y la flota disponible cuando el Operador solicite la optimización, minimizando distancia, combustible, emisiones de CO₂ y penalizaciones por ventanas de tiempo, respetando restricciones de conductores y de tránsito.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existen pedidos pendientes y vehículos/conductores disponibles  
CUANDO el Operador solicita la generación de rutas  
ENTONCES el sistema ejecuta la metaheurística seleccionada (GA / Tabú / ACO), genera rutas válidas en ≤ 45 segundos (hasta 150 pedidos y 15 vehículos) y las presenta para confirmación.

#### Ruta Feliz
DADO que se aplica restricción vehicular por dígito de placa o se incorporan datos de tráfico en tiempo real  
CUANDO se genera la ruta  
ENTONCES el sistema excluye vehículos restringidos ese día y ajusta tiempos de viaje según el nivel de congestión.

#### Ruta Infeliz
DADO que no hay vehículos disponibles o el algoritmo no encuentra solución factible dentro del tiempo límite  
CUANDO se solicita la optimización  
ENTONCES el sistema notifica el fallo, mantiene el estado anterior y sugiere acciones correctivas (agregar vehículos, relajar ventanas, etc.).

---

### RF-004: Visualización de Rutas en Mapa
- **Descripción Atómica:** El sistema debe mostrar las rutas optimizadas en un mapa interactivo cuando el usuario seleccione una ruta o un conjunto de rutas generadas.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existen rutas generadas  
CUANDO el usuario selecciona una ruta  
ENTONCES el sistema renderiza el trazado, los puntos de entrega, el tiempo estimado por tramo y el nivel de congestión (verde/amarillo/rojo) sobre un mapa base con límites distritales.

#### Ruta Feliz
DADO que existen zonas de alto riesgo de seguridad  
CUANDO se visualiza la ruta  
ENTONCES el sistema marca dichas zonas y permite al usuario solicitar una ruta alternativa más segura.

#### Ruta Infeliz
DADO que el servicio de mapas no está disponible  
CUANDO se intenta visualizar  
ENTONCES el sistema muestra un mensaje de error y ofrece una vista tabular de la secuencia de entregas como respaldo.

---

### RF-005: Dashboard de Indicadores de Sostenibilidad
- **Descripción Atómica:** El sistema debe mostrar en tiempo real los indicadores de distancia, emisiones de CO₂, combustible ahorrado, cumplimiento de ventanas de tiempo y equivalentes ambientales cuando el usuario acceda al dashboard.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que el usuario tiene rol de Gerente u Operador  
CUANDO accede al dashboard  
ENTONCES el sistema muestra las métricas actualizadas (km, kg CO₂, litros, %, soles ahorrados y equivalentes en árboles).

#### Ruta Feliz
DADO que el usuario es Conductor  
CUANDO accede al “modo conductor”  
ENTONCES el sistema muestra solo la versión simplificada (ruta asignada, entregas pendientes y alertas).

#### Ruta Infeliz
DADO que no hay datos de rutas del día  
CUANDO se consulta el dashboard  
ENTONCES el sistema muestra valores en cero con mensaje “Sin datos de operación para el período seleccionado”.

---

### RF-006: Reportes de Sostenibilidad
- **Descripción Atómica:** El sistema debe generar y permitir la descarga de un reporte PDF con el resumen de impacto ambiental y económico cuando el usuario solicite un reporte de un período determinado.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existen datos de rutas del período solicitado  
CUANDO el usuario solicita el reporte PDF  
ENTONCES el sistema genera el documento con emisiones por ruta, costo del ciclo de vida, ahorro en combustible y cumplimiento de metas, y permite su descarga.

#### Ruta Feliz
DADO que se incluyen costos locales (combustible S/ 17.50/galón, mantenimiento S/ 1.20/km)  
CUANDO se genera el reporte  
ENTONCES el sistema utiliza dichos valores para los cálculos económicos.

#### Ruta Infeliz
DADO que el período seleccionado no tiene datos  
CUANDO se solicita el reporte  
ENTONCES el sistema informa que no hay información disponible y no genera el archivo.

---

### RF-007: Re-optimización Dinámica
- **Descripción Atómica:** El sistema debe recalcular las rutas afectadas cuando se registre un nuevo pedido, una cancelación, un accidente de tránsito o una avería de vehículo.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que ocurre un evento que invalida rutas existentes (nuevo pedido, cancelación, incidente)  
CUANDO el sistema detecta el evento o el Operador lo confirma  
ENTONCES el sistema re-optimiza las rutas afectadas en ≤ 30 segundos y notifica a los conductores involucrados.

#### Ruta Feliz
DADO que se incorporan datos de incidentes en tiempo real (Waze CCP / SIMAT)  
CUANDO se re-optimiza  
ENTONCES el sistema evita las zonas afectadas y genera rutas alternativas.

#### Ruta Infeliz
DADO que no es posible encontrar una solución factible dentro del tiempo límite  
CUANDO se intenta re-optimizar  
ENTONCES el sistema mantiene las rutas anteriores, notifica el fallo y registra el evento para revisión manual.

---

### RF-008: Gestión de Conductores
- **Descripción Atómica:** El sistema debe permitir registrar, consultar y actualizar los datos de los conductores, incluyendo restricciones de jornada y punto de partida, cuando un usuario autorizado realice la operación.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que el usuario tiene permisos de Administrador u Operador  
CUANDO registra un conductor con nombre, DNI, licencia, experiencia, disponibilidad horaria y contacto  
ENTONCES el sistema almacena el registro y valida que la jornada no exceda 8 horas diarias.

#### Ruta Feliz
DADO que el conductor vive en un distrito alejado  
CUANDO se asigna una ruta  
ENTONCES el sistema considera su punto de partida real para el cálculo de tiempos.

#### Ruta Infeliz
DADO que se intenta asignar una jornada superior a 8 horas o sin el descanso obligatorio  
CUANDO se guarda la asignación  
ENTONCES el sistema rechaza la operación y muestra el mensaje de incumplimiento de la Ley N° 30224.

---

### RF-009: Módulo de Preferencias de Clientes
- **Descripción Atómica:** El sistema debe permitir a los clientes (o al Operador en su nombre) registrar y actualizar preferencias de entrega (horarios, puntos de referencia, restricciones de acceso) cuando se gestione la ficha del cliente.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que el cliente o el Operador tiene acceso a la ficha  
CUANDO registra horarios preferidos, puntos de referencia y restricciones de acceso  
ENTONCES el sistema almacena las preferencias y las considera en futuras optimizaciones.

#### Ruta Feliz
DADO que el cliente es una bodega con horario variable  
CUANDO se registran ventanas de atención (ej. 06:00-21:00)  
ENTONCES el sistema las utiliza como restricción suave en el algoritmo.

#### Ruta Infeliz
DADO que se ingresan horarios inválidos o contradictorios  
CUANDO se intenta guardar  
ENTONCES el sistema rechaza la operación y solicita corrección.

---

### RF-010: Plan de Compensación de Carbono
- **Descripción Atómica:** El sistema debe calcular el CO₂ total emitido en un período y proponer un plan de compensación (cantidad de árboles o alianzas de reforestación) cuando el usuario solicite el cálculo de compensación.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existen datos de emisiones del período  
CUANDO el usuario solicita el plan de compensación  
ENTONCES el sistema calcula el CO₂ emitido, estima la cantidad de árboles necesarios y sugiere proyectos locales (Lomas de Lima, Parque Zonal Huáscar, “Árboles para Lima”).

#### Ruta Feliz
DADO que se dispone de factores de compensación actualizados  
CUANDO se genera el plan  
ENTONCES el sistema muestra el equivalente en árboles y el costo estimado de la compensación.

#### Ruta Infeliz
DADO que no hay datos de emisiones  
CUANDO se solicita el plan  
ENTONCES el sistema informa que no es posible calcular la compensación por falta de datos.

---

### RF-011: Autenticación, Usuarios y Roles
- **Descripción Atómica:** El sistema debe autenticar a los usuarios y aplicar el control de acceso por roles (RBAC) definido en el documento 08 cuando un usuario intente iniciar sesión o acceder a cualquier módulo.
- **Prioridad:** Alta
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que existe un usuario activo con rol asignado (Administrador, Gerente, Operador, Conductor o Auditor)  
CUANDO ingresa credenciales válidas  
ENTONCES el sistema genera un token de sesión, registra el acceso en el log de auditoría y habilita únicamente los módulos permitidos para su rol.

#### Ruta Feliz
DADO que el Administrador gestiona la lista de usuarios  
CUANDO crea, modifica el rol o desactiva a un usuario  
ENTONCES el sistema aplica el cambio de permisos y deja constancia del evento en el log de auditoría.

#### Ruta Infeliz
DADO que un usuario acumula 3 intentos fallidos consecutivos de inicio de sesión  
CUANDO intenta autenticarse nuevamente  
ENTONCES el sistema bloquea la cuenta durante 15 minutos, no revela si el usuario existe y registra el evento (RN-019).

---

### RF-012: Administración de Parámetros y Auditoría del Sistema
- **Descripción Atómica:** El sistema debe permitir al Administrador consultar y actualizar los parámetros de configuración utilizados por el motor de optimización y por los cálculos de sostenibilidad, así como consultar los registros de auditoría.
- **Prioridad:** Media
- **Criterios de Aceptación (Gherkin / BDD):**

#### Ruta Gold
DADO que el usuario tiene rol de Administrador  
CUANDO actualiza un parámetro de configuración (tiempo máximo de cómputo, pesos de la función objetivo, precio del combustible, factor de captura de CO₂ por árbol)  
ENTONCES el sistema guarda el nuevo valor, lo aplica a las siguientes optimizaciones y registra el cambio en el log de auditoría.

#### Ruta Feliz
DADO que el Auditor o el Administrador necesita evidencia de cumplimiento  
CUANDO consulta el log de auditoría filtrando por fecha, usuario o acción  
ENTONCES el sistema muestra los eventos críticos registrados (RNF-010) sin permitir su modificación.

#### Ruta Infeliz
DADO que se intenta guardar un parámetro fuera de los rangos permitidos (ej. tiempo máximo de cómputo mayor a 45 segundos)  
CUANDO se envía el formulario  
ENTONCES el sistema rechaza el cambio y conserva el valor anterior, para no vulnerar RNF-001 ni RN-014.

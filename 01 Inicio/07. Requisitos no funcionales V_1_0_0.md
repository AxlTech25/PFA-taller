## 1. Introducción

Los requisitos no funcionales definen los **atributos de calidad** del sistema EcoLogística Lima. Se especifican mediante **Escenarios de Calidad** según el modelo **ISO/IEC 25010** y el enfoque **arc42**, utilizando métricas **SMART** (específicas, medibles, alcanzables, relevantes y temporales).  

Queda prohibido el uso de adjetivos calificativos sin umbral cuantitativo explícito.

## 2. Catálogo de Requisitos No Funcionales

### RNF-001: Rendimiento del Algoritmo de Optimización
- **Categoría ISO 25010:** Eficiencia de Desempeño (Time Behaviour)
- **Escenario de Calidad:**
  - **Fuente:** Operador de logística
  - **Estímulo:** Solicitud de generación de rutas para hasta 150 pedidos y 15 vehículos
  - **Entorno:** Carga normal de operación (horario 05:00–22:00)
  - **Artefacto:** Módulo de Optimización (metaheurística VRPTW + Green VRP)
  - **Respuesta:** Generar una solución válida y factible
  - **Medida (SLA):** Tiempo de respuesta ≤ 45 segundos en el percentil 95 (P95). Para re-optimización dinámica ≤ 30 segundos en el P95.

### RNF-002: Seguridad (OWASP Top 10 + Ley N° 29733)
- **Categoría ISO 25010:** Seguridad (Confidentiality, Integrity, Authenticity)
- **Escenario de Calidad:**
  - **Fuente:** Atacante externo o usuario no autorizado
  - **Estímulo:** Intento de inyección SQL, XSS, CSRF o acceso no autorizado a datos personales de conductores/clientes
  - **Entorno:** Producción
  - **Artefacto:** API Backend + Base de Datos + Capa de autenticación
  - **Respuesta:** Bloquear la petición, registrar evento de auditoría y denegar el acceso
  - **Medida (SLA):** 0 vulnerabilidades críticas OWASP Top 10 explotables. Cumplimiento 100% de la Ley N° 29733 (consentimiento explícito, cifrado en reposo AES-256 y en tránsito TLS 1.3).

### RNF-003: Accesibilidad
- **Categoría ISO 25010:** Usabilidad (Accessibility)
- **Escenario de Calidad:**
  - **Fuente:** Conductor con baja familiaridad tecnológica o limitación visual leve
  - **Estímulo:** Acceso al “modo conductor” o al dashboard principal
  - **Entorno:** Dispositivo móvil con conexión 2G/3G
  - **Artefacto:** Interfaz de usuario (SPA)
  - **Respuesta:** Presentar interfaz usable con iconos grandes, alto contraste y navegación simple
  - **Medida (SLA):** Cumplimiento 100% de los criterios WCAG 2.1 nivel AA. Tiempo de aprendizaje de la interfaz básica ≤ 10 minutos para usuarios con educación básica.

### RNF-004: Escalabilidad
- **Categoría ISO 25010:** Eficiencia de Desempeño (Resource Utilization) / Capacidad
- **Escenario de Calidad:**
  - **Fuente:** Crecimiento de la operación
  - **Estímulo:** Incremento de carga hasta 1 000 pedidos diarios y 50 vehículos
  - **Entorno:** Operación normal con auto-scaling habilitado
  - **Artefacto:** Arquitectura de contenedores / servicios backend
  - **Respuesta:** Mantener los tiempos de respuesta definidos en RNF-001 sin degradación superior al 20%
  - **Medida (SLA):** El sistema debe soportar 1 000 pedidos/día y 50 vehículos concurrentes con degradación de latencia ≤ 20% respecto a la carga base (150 pedidos / 15 vehículos).

### RNF-005: Usabilidad (Modo Conductor)
- **Categoría ISO 25010:** Usabilidad (Operability, User Error Protection)
- **Escenario de Calidad:**
  - **Fuente:** Conductor de reparto
  - **Estímulo:** Consulta de ruta asignada, entregas pendientes y alertas de tráfico
  - **Entorno:** Dispositivo móvil en movimiento, posible baja conectividad
  - **Artefacto:** Vista “Modo Conductor”
  - **Respuesta:** Mostrar únicamente la información esencial de forma clara y con mínima interacción
  - **Medida (SLA):** Tasa de error de usuario ≤ 5% en tareas críticas (consultar siguiente entrega, confirmar entrega). Tiempo de carga de la vista ≤ 3 segundos en red 3G.

### RNF-006: Disponibilidad
- **Categoría ISO 25010:** Fiabilidad (Availability)
- **Escenario de Calidad:**
  - **Fuente:** Infraestructura cloud o corte de energía local
  - **Estímulo:** Caída de un nodo o pérdida temporal de conectividad
  - **Entorno:** Horario operativo 05:00–22:00
  - **Artefacto:** Sistema completo (frontend + backend + base de datos)
  - **Respuesta:** Mantener el servicio disponible o activar mecanismo de contingencia (caché local / modo offline limitado)
  - **Medida (SLA):** Disponibilidad ≥ 99.5% en horario operativo (05:00–22:00). RTO ≤ 5 minutos para fallos de nodo.

### RNF-007: Documentación
- **Categoría ISO 25010:** Mantenibilidad (Analysability) / Portabilidad
- **Escenario de Calidad:**
  - **Fuente:** Nuevo integrante del equipo o auditor académico
  - **Estímulo:** Necesidad de comprender arquitectura, API o procedimientos de operación
  - **Entorno:** Repositorio del proyecto
  - **Artefacto:** Documentación técnica y de usuario
  - **Respuesta:** Proporcionar documentación completa, actualizada y navegable
  - **Medida (SLA):** Existencia de: (1) Documentación de arquitectura (C4), (2) Manual de usuario, (3) Manual de administrador, (4) Documentación de API (OpenAPI/Swagger), (5) Análisis del contexto logístico de Lima. Cobertura ≥ 90% de los módulos implementados.

### RNF-008: Precisión Funcional del Algoritmo
- **Categoría ISO 25010:** Adecuación Funcional (Functional Correctness)
- **Escenario de Calidad:**
  - **Fuente:** Operador
  - **Estímulo:** Ejecución del algoritmo de optimización
  - **Entorno:** Conjunto de pedidos y flota válidos
  - **Artefacto:** Motor de optimización
  - **Respuesta:** Generar rutas que respeten todas las restricciones (capacidad, ventanas de tiempo, jornadas de conductores, restricción vehicular)
  - **Medida (SLA):** 100% de las soluciones generadas deben ser factibles (ninguna violación de restricción dura). Desviación máxima de la función objetivo respecto a una solución de referencia ≤ 15% en escenarios de prueba controlados.

### RNF-009: Bajo Consumo de Datos (Conectividad Limitada)
- **Categoría ISO 25010:** Eficiencia de Desempeño (Resource Utilization)
- **Escenario de Calidad:**
  - **Fuente:** Conductor en zona periférica
  - **Estímulo:** Uso del modo conductor o visualización de mapa
  - **Entorno:** Red 2G/3G con ancho de banda limitado
  - **Artefacto:** Frontend móvil
  - **Respuesta:** Cargar y actualizar la información esencial con el mínimo de datos transferidos
  - **Medida (SLA):** Consumo de datos de la vista “Modo Conductor” ≤ 150 KB por sesión de consulta de ruta. Tiempo de carga inicial ≤ 5 segundos en red 3G simulada.

### RNF-010: Cumplimiento Normativo y Trazabilidad
- **Categoría ISO 25010:** Seguridad (Non-repudiation) / Cumplimiento
- **Escenario de Calidad:**
  - **Fuente:** Auditor o autoridad (docente / MTC)
  - **Estímulo:** Solicitud de evidencia de cumplimiento de jornadas laborales o de protección de datos
  - **Entorno:** Sistema en producción o ambiente de auditoría
  - **Artefacto:** Módulo de auditoría y logs
  - **Respuesta:** Proporcionar registros inalterables de asignaciones de rutas, jornadas de conductores y accesos a datos personales
  - **Medida (SLA):** Todos los eventos críticos (login, asignación de ruta, modificación de datos personales, generación de reportes) deben quedar registrados con timestamp, usuario y acción. Retención mínima de logs: 12 meses.

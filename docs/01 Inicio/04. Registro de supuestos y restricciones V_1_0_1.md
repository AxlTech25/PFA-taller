## 1. Tabla de Supuestos (Assumptions)

| ID    | Descripción del supuesto                                                                 | Categoría (Técnica / Operativa / Financiera) | Grado de Impacto (Alto / Medio / Bajo) | Estrategia de Validación                                      |
|-------|------------------------------------------------------------------------------------------|----------------------------------------------|----------------------------------------|---------------------------------------------------------------|
| S-01  | Se dispondrá de acceso a APIs de tráfico (Waze CCP o Google Maps) con datos suficientemente precisos para las vías principales de Lima. | Técnica                                      | Alto                                   | Pruebas de integración tempranas y comparación con datos reales de campo |
| S-02  | El equipo universitario cuenta con los conocimientos necesarios en Python, frameworks web y metaheurísticas para completar el MVP en 14 semanas. | Operativa                                    | Alto                                   | Evaluación inicial de competencias y plan de capacitación     |
| S-03  | Las direcciones de entrega en San Juan de Lurigancho podrán geocodificarse o complementarse con puntos de referencia de forma confiable. | Técnica                                      | Alto                                   | Pruebas de geocodificación y validación con conductores       |
| S-04  | El presupuesto de S/ 500,000 será suficiente para el desarrollo del MVP incluyendo costos de cloud e integraciones. | Financiera                                   | Medio                                  | Seguimiento presupuestal quincenal y control de cambios       |
| S-05  | Los conductores adoptarán el sistema si se les proporciona un modo simplificado e intuitivo (“modo conductor”). | Operativa                                    | Medio                                  | Pruebas de usabilidad y feedback de usuarios reales           |
| S-06  | Existirá disponibilidad de datos históricos o simulados de pedidos y flota de DistriRápido para entrenar y probar el algoritmo. | Técnica                                      | Medio                                  | Generación de datasets sintéticos realistas y validación      |
| S-07  | Las restricciones de restricción vehicular (último dígito de placa) y horarios de conductores se mantendrán estables durante el proyecto. | Operativa                                    | Bajo                                   | Monitoreo de cambios normativos del MTC                       |

## 2. Tabla de Restricciones (Constraints)

| C-12  | El sistema debe poder escalar hasta 1,000 pedidos diarios y 50 vehículos sin rediseño de arquitectura. | Tecnología | Media | Media |
